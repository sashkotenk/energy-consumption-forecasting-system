# Release-readiness evidence pack

This directory contains public, reproducible evidence for the EnergyForecast coursework release candidate. It intentionally contains no private planning material, raw UCI data, user uploads, generated model bundles, database volumes or secrets.

## Contents

- `security-review.md` — final review of upload, path, SQL, CORS, secret, deserialization and container trust boundaries.
- `release-benchmark.json` — measured deterministic synthetic benchmark generated by `scripts/generate_release_benchmark.py` on a CI runner. It is added only after an actual benchmark run; values are never invented.
- `verification.md` — exact commands, test counts, CI run references, migration/contract results and known warnings for the release-candidate verification run.
- `screenshots/` — representative browser screenshots captured by the deterministic Playwright primary flow.
- `handoff-manifest.json` — point-5 handoff metadata and SHA-256 checksums for committed evidence files.

## Generate performance evidence

From `backend` after locked dependency synchronization:

```bash
uv run --frozen python ../scripts/generate_release_benchmark.py --output ../build/release-benchmark.json
```

The generator records the runner CPU, logical CPU count, total memory, Python version, seed/profile semantics and measured timings for:

- streaming parser on 50,000 deterministic UCI-shaped rows;
- quality evaluation on 10,000 deterministic minute records;
- 24 hours of minute-to-hour transformation;
- bounded analytics bucket selection;
- FastAPI liveness request latency through the ASGI stack;
- Ridge direct-24 training median (three measured fits after warmup), prediction median/p95 (30 repetitions) and serialized model size.

The benchmark is an engineering performance profile, not the final UCI scientific experiment. Full-dataset profiling requires an external `ENERGYFORECAST_UCI_PATH` and remains outside Git because the original UCI file is intentionally not committed.

## Capture browser evidence

The Playwright primary flow uses deterministic synthetic API responses and writes screenshots at stable workflow checkpoints. CI uploads the screenshots as an artifact. The committed screenshots in this evidence pack are copied from a successful TASK-22 evidence-collection run.

## Verify documentation and evidence

From the repository root:

```bash
python scripts/verify_documentation.py
python scripts/verify_evidence.py
```

The first command validates repository-local Markdown links and Mermaid source structure. The second recomputes SHA-256 values in `handoff-manifest.json` and fails on missing or modified evidence files.

The repository-wide `scripts/verify.ps1` gate invokes both checks in addition to backend, database, OpenAPI/SDK, frontend and private-file verification.

## Provenance rule

`verification.md`, `release-benchmark.json` and screenshot entries must identify the GitHub Actions run from which the evidence was collected. If a later code change invalidates evidence, regenerate it and update the checksum manifest rather than editing measurements manually.
